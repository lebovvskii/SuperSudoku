# SuperSudoku

Личное судоку без рекламы: PWA, офлайн-режим, честная логическая проверка, три ошибки и пять последовательно открываемых уровней.

## Запуск

Нужен Node.js 24 (тесты серверной БД используют встроенный `node:sqlite`). У фронтенда нет зависимостей.

```sh
npm run dev      # http://localhost:4173
npm test         # движок, сохранения, синхронизация и API
npm run check    # синтаксис + тесты
npm run build    # статический PWA в dist/
```

Для браузерных тестов нужен установленный Playwright и Chromium. `npm run test:e2e` запускается с доступным локальным сервером. Статическая версия сохраняет прогресс локально; облачный API появляется только в hosted-сборке.

## Возможности

- Адаптивное поле 9 × 9, клавиатура и сенсорный ввод, заметки, отмена, ластик, пауза и бесплатные логические подсказки.
- Три **доказанные** ошибки завершают игру. Повтор той же ошибочной цифры на неизменном поле не снимает ещё одну жизнь. Отмена не возвращает жизни.
- Начальный, лёгкий, средний, сложный и экспертный уровни. Для следующих нужны 2, 5, 9 и 14 побед всего и хотя бы одна победа на непосредственно предыдущем уровне.
- 25 исходных головоломок с единственным решением, проверенных по сложности. Перестановки цифр, строк, столбцов и транспонирование дают мгновенные воспроизводимые варианты без сетевых запросов.
- История, лучшее время и открытые уровни. IndexedDB плюс аварийная локальная копия. JSON-экспорт и восстановление.
- Service worker, installable manifest, адаптивные иконки и автономный режим после первого открытия.
- Светлая и тёмная темы, семантические кнопки, клавиатурный ввод и видимый фокус.

## Почему проверка не подсказывает угадывать

`validateEntry` **никогда не смотрит в готовое решение**. Она использует только исходные цифры и введённые записи, которые уже доказаны поддерживаемой логикой. Приёмы: одиночный кандидат, скрытый одиночный, заблокированные кандидаты и открытая пара.

Если цифра пока не доказана и не опровергнута, ввод нейтрален независимо от того, совпадает ли он с ответом. Такие записи не становятся предпосылками для штрафов в других клетках. Не введённые игроком выводы не заполняют поле и не превращают проверку в решатель всей задачи. Старые нейтральные записи не штрафуются автоматически, если позже обнаружится противоречие. Завершение проверяется по правилам судоку, а не сравнением с ответом.

Это консервативная проверка, а не обещание распознавать любую возможную человеческую стратегию. На экспертном уровне подсказка может честно сообщить, что поддерживаемых приёмов недостаточно.

## База данных и приватное размещение

`hosting/` содержит адаптер Sites/Vinext с Cloudflare D1 и входом через ChatGPT. Сайт закрыт для посторонних. Сохранения привязаны к ID вошедшего пользователя; ключей БД во фронтенде нет. Сервер проверяет происхождение запросов и использует атомарные версии, чтобы два устройства не перезаписали прогресс друг друга. При конфликте пользователь выбирает версию. Офлайн-игра продолжает сохраняться на устройстве.

Подробнее: [hosting/README.md](hosting/README.md).

```sh
cd hosting && npm ci && cd ..
npm run build:hosted
```

Сборка сайта выдаёт Worker, ресурсы PWA и миграции D1 в `dist/`. Не заменяйте hosted-публикацию статическим `dist/`, если нужна облачная синхронизация. Не меняйте доступ сайта на публичный без проверки авторизации и конфиденциальности.

## Управление

- 1–9: цифра; N: режим заметок.
- Стрелки: выбор клетки; Backspace/Delete/0: очистить.
- Ctrl/Cmd + Z: отменить ввод, не штраф.

Сохранения браузера могут исчезнуть при очистке данных или удалении приложения. Облачная копия и экспорт помогают восстановить прогресс; полезно время от времени скачивать резервную копию.
